# Таймаут, экран 429 и локальный Swagger

## Что делает форма

- На одну отправку выполняется один POST; автоматического повтора нет.
- Через 10 секунд браузер прекращает ждать ответ. Это **не отменяет** уже принятую n8n заявку, поэтому сайт предупреждает сначала проверить выполнение, а не отправлять повторно.
- При HTTP 429 сайт показывает отдельное заметное сообщение и не повторяет заявку автоматически.
- Пока запрос обрабатывается, кнопка заблокирована, чтобы случайное двойное нажатие не создало второй POST.

## Как открыть сайт и Swagger локально

Нужны Node.js и npm. В терминале перейдите в папку `my_app/app` и выполните:

```bash
npm install
npm run local
```

В терминале появятся два локальных адреса:

- сайт: `http://localhost:8000/`
- Swagger UI: `http://localhost:8000/swagger`

Swagger UI и его JavaScript/CSS обслуживаются из установленного npm-пакета на localhost; отдельный Swagger-сервис или Vercel для открытия документации не нужны. OpenAPI-описание лежит в `openapi.json`.

Кнопка **Try it out** отправляет настоящий POST в указанный в OpenAPI учебный production webhook n8n. Это может создать строку в таблице и сообщение в тестовом Telegram-чате. Используйте только синтетические данные и не нажимайте Execute для проверки без необходимости.

Чтобы остановить локальный сервер, нажмите `Ctrl+C` в терминале.

## Проверка 429

Обычный webhook может не возвращать 429 сам по себе. Экран появится, когда ответ интеграции действительно имеет статус 429. Не создавайте нагрузку на рабочий endpoint для демонстрации. Для гарантированной репетиции настройте временный mock на отдельной тестовой копии или используйте DevTools, чтобы отдельно проверить визуальный макет.


## GET Hello World в Swagger

Локальный сервер также реализует `GET http://localhost:8000/hello`, который возвращает JSON `{"message":"Hello, world!"}`. В Swagger раскройте **GET /hello** и нажмите **Try it out → Execute**. Запрос обрабатывается локально и не запускает workflow n8n.


`GET /hello` ограничен локальным сервером: от одного клиента принимается один запрос за 10 секунд. Более ранний повтор получает HTTP 429 и заголовок `Retry-After` с оставшимся временем ожидания. Ограничение действует отдельно для этого локального маршрута; оно не настраивает лимит в облачном n8n.
