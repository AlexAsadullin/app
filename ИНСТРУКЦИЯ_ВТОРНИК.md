# Материалы ко вторнику: окружения и секреты

## Что показывает сайт

В нижней учебной карточке кратко объяснены локальная среда, Preview и Production, F02 (`POST /undefined` и 404 от Vercel), отличие от F01 (404 от n8n) и дополнительная ситуация 401. Отдельно указано, что адрес `WEBHOOK_URL`, встроенный в клиентский JavaScript, публичен и не должен содержать токенов.

## Демонстрация F02 на учебном проекте Vercel

1. В Project Settings → Environment Variables проверьте `WEBHOOK_URL`. Для первого шага оставьте её включённой в Preview и выключенной в Production. Не открывайте и не демонстрируйте значение.
2. Запустите новый Preview-деплой и новый Production-деплой, чтобы настройки попали в сборки.
3. В журнале Production найдите `WEBHOOK_URL = undefined`; в интерфейсе сайта подтвердите окружение и отсутствие переменной.
4. Отправьте синтетическую заявку на Preview: она должна дойти до учебной цепочки. На Production отправка уйдёт на `/undefined`; в Network будет 404 `NOT_FOUND` от Vercel. В n8n не должно появиться выполнения с Production.
5. Сравните с F01: там запрос отправлен на n8n, и тело ответа говорит `The requested webhook ... is not registered`; сервер n8n ответил 404.
6. Теперь добавьте `WEBHOOK_URL` для Production (это только публичный адрес учебного webhook, не токен), сохраните настройку и создайте новый Production-деплой. Переменная применяется к новой сборке.
7. Откройте рабочий Production URL и отправьте одну синтетическую заявку с уникальным словом. Успех подтверждён только если совпадающий код виден в n8n Executions, учебной таблице и тестовом чате. Запишите время и фактический результат.

### Локальная симуляция сборки

Из папки `my_app/app`:

- `npm run build` без переменной воспроизводит `WEBHOOK_URL = undefined`.
- `WEBHOOK_URL='https://example.invalid/webhook/zayavka' APP_ENV=Preview npm run build` демонстрирует заданную настройку. `example.invalid` — безопасный фиктивный адрес; такая сборка не отправит заказ.

Не используйте этот фиктивный адрес для приёмочного smoke-теста. Для проверки рабочего адреса нужен заранее настроенный учебный webhook и учебные интеграции.

## Пример 401

Карточка на странице отмечает 401 как дополнительный пример, а не как один из журналов F01–F07. Ученик должен определить узел и сервис, проверить выбранное подключение и права; не маскировать ошибку повторными попытками.

## Безопасность и границы

- В браузерном `config.js` адрес webhook виден посетителю. В этой форме он используется как открытый endpoint, не как секрет.
- Токены Telegram, пароли и секретные API-ключи нельзя собирать в `public/config.js` или передавать фронтенду. Для сервисов используйте Credentials на стороне n8n.
- Все прогоны выполняйте на учебной копии, с синтетическими данными и отдельным тестовым чатом.
- Проверка сборки не подтверждает доступность реального Production URL. Этот workspace не подключён к вашему аккаунту Vercel, поэтому настройки Vercel и внешняя публикация выполняются в аккаунте владельца проекта.
