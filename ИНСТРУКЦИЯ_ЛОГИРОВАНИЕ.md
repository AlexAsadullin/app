# Локальный лог и Telegram-уведомление о rate limit

Сборка `npm run build` не менялась. Для локального журнала из папки `my_app/app` сначала выполните `npm run build`, затем `node dev-server.js`. Откройте локальный сайт по адресу из терминала. События формы будут дописываться в `actions.log` в этой папке (по одной JSON-строке на событие). В журнал попадают только тип действия, время, окружение, HTTP-статус/таймер; имя, телефон, заказ и комментарий не пишутся. Файл `actions.log` локальный и не включён в Git.

При попытке отправить форму раньше окончания десятисекундного cooldown фронтенд отправляет минимальное уведомление в отдельный webhook n8n `rate-limit-violation`. Этот webhook соединён с Telegram-узлом в обновлённом `week-10-v2-materials/kopiya-cepochki/n8n/zayavka-workflow.json`. Импортируйте обновлённый workflow (или вручную перенесите два новых узла), укажите Telegram Credentials и Chat ID тестовой группы в `Telegram · rate limit`, затем активируйте workflow. Уведомление отправляется максимум раз за cooldown на браузер и не содержит данных заявки.

Это браузерный cooldown: его можно обойти прямым HTTP-запросом или очисткой браузерного хранилища. Для жёсткого серверного rate limit нужен backend-side limiter.
